# Reinaldo León — professional bio

Static GitHub Pages site. The homepage is hand-authored in `index.html`; styling and interactions live in `assets/css/style.css` and `assets/js/main.js`. The `.nojekyll` file means GitHub Pages serves committed files directly.

## Writing

Long-form articles live in `content/writing/*.md` (English) and `content/writing/es/*.md` (Spanish) with YAML frontmatter. Every English source requires a complete Spanish companion with the same filename. `tools/build_writing.py` generates bilingual public `writing/` pages, `writing/feed.xml` and `sitemap.xml`. Generated files are committed alongside their Markdown sources. Both language bodies are present in the static HTML; the shared language selector displays the reader's chosen language.

Run:

```sh
uv sync
uv run python tools/build_diagrams.py
uv run python tools/build_writing.py
```

Then preview the repository root with a static server, for example `python3 -m http.server 8000`, and open `http://localhost:8000/`.

Copy both `content/writing/_template.md` and `content/writing/es/_template.md` to filenames matching the article `slug`. English required frontmatter: `title`, `slug`, `date` (YYYY-MM-DD), `description`, `tags` (list) and `pillar`. The Spanish companion requires `title`, `description` and a full translated body. Optional English fields: `project`, `draft`, `featured`, `linkedin_text`, `linkedin_url`, `linkedin_published_at`. Drafts are omitted from the generated index, feed and sitemap. `project` accepts `growthmesh`, `causio`, `ecos-inmersivos` or `ai-conversacional-lab` and links to the related homepage card. Add a new project to `PROJECTS` in the build script when it is added to the homepage.

Editorial rule: titles should ask a recognizable question or state a common problem. The article must offer practical orientation from experience without suggesting a universal formula or an unsupported outcome. Keep English and Spanish titles equivalent, and preserve the slug when revising a published title so existing links remain stable.

For a flow illustration, set `diagram`, `diagram_alt` and `diagram_caption` in the English source, and `diagram_alt` and `diagram_caption` in its Spanish companion. The builder then requires `assets/images/flows/<diagram>-en.svg` and `<diagram>-es.svg`. The current diagrams are generated from editable labels in `tools/build_diagrams.py`. An article can omit the diagram fields when a flow would not help.

For a larger editorial illustration, use `illustration_en` and `illustration_es` with filenames in `assets/images/writing/`, plus `illustration_alt` and `illustration_caption` in both Markdown files. The two images may use different supported formats; readers can open either image at full size. Use an illustration or a flow diagram, not both.

Long articles can opt into separate canonical routes by setting `localized_routes: true`, `slug_es`, `subtitle` and `diagram_prefix` in the English frontmatter, plus a Spanish `subtitle`. The generator then writes `/en/writing/<slug>/` and `/es/writing/<slug_es>/` from the same Markdown pair; each page has its own canonical, reciprocal hreflang, locale-specific social card, metadata and JSON-LD. Add `diagrams` lists with matching IDs and localized `alt` and `caption` in both frontmatters, then put `{{diagram:id}}` on its own line where each figure belongs. SVG filenames follow `assets/images/flows/<diagram_prefix>-<id>-<lang>.svg`; social PNGs follow `assets/images/writing/<slug>-<lang>.png`. Existing single-URL articles retain their current routing.

The agent adoption article's diagrams are generated by `uv run python tools/build_agent_diagrams.py`. Its optional social-card editor is `python3 tools/build_agent_social.py` (requires Pillow); the committed PNGs are served without a runtime dependency.

The coding-agent traceability article uses the same SVG helpers through `uv run python -m tools.build_traceability_diagrams`. Its localized social previews can be rebuilt with `python3 -m tools.build_traceability_social` (Pillow required only for regeneration).

## Review before publishing

Run the builder, check `git diff --check`, review the generated HTML and verify public claims and Cobee confidentiality. Pushing the `gh-pages` branch publishes the committed static files; this repository does not run an automatic build.
